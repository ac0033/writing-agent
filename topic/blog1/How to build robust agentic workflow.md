标题：让 Agent 可靠地干活——一套防御纵深的工程框架

一、问题：Agent 为什么不可靠？（动机）
   - 两个犯错域：安全 & 任务
   - 核心矛盾：强大生成力 × 零可靠性保证

二、单个 Agent 的搭建
   2.1 Context：分层记忆、Token预算、信息时效、来源约束
   2.2 Tools：能力集定义、权限边界、沙箱隔离
   2.3 LLM：模型选择、参数配置、能力边界声明
   2.4 单 Agent Harness
       - 预防：Schema约束、断言前置、反例注入、输出过滤
       - 检测：自验证、置信度、局部可观测
       - 恢复：单节点重试、自修复循环

三、Agent 协作框架
   3.1 拓扑结构：串行/并行/DAG/循环/树状，选择原则
   3.2 节点定义与连接：每节点四要素、State管理、通信协议
   3.3 协作层 Harness
       - 预防：最小权限传递、Agent间消息校验、速率配额
       - 检测：Critic Agent、多Agent投票、跨节点一致性、HITL
       - 恢复：消息回滚、部分重跑、降级、熔断、升级链
       - 可观测性：全链路Trace、Metrics、回放
       - 成本与效率：模型分层、并行化、预算熔断
   3.4 持续改进闭环：失败归档→归因→更新→验证

   - 核心观点：可靠性是系统工程的函数，不是模型能力的函数
