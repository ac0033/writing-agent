# AI OS终端对话

启动：在项目根目录执行 `uv run python tui.py`。Windows无需curses。首次依赖安装使用`uv sync`。

TUI 是与 AI OS 交互的完整入口：开始新文章、审阅并确认摘要、运行中发送纠正、回答 AI OS 的提问、选择短样稿、追加预算、终审确认并保存、发布预览与发布确认，都在页面上完成，不需要再经由 Claude Code / Codex 对话转发。Claude Code、Codex 只作为 AI OS 和部分专业节点的非交互式模型入口被调用。

## 页面元素

启动后先出现“选择 AI OS 模型”开始页（见下文“接入设置”）。主页面只显示当前阶段用得上的输入和按钮；快捷键不显示在页脚，点顶栏“快捷键”或按 F1 查看。

| 位置 | 元素 | 作用 |
|---|---|---|
| 顶栏 | 历史 | 按来源分组：本机任务、登记的其他任务目录、已发布文章（只读）；选中后页面重新展示待确认内容或已保存正文 |
| 顶栏 | 接入 | 重新打开“选择 AI OS 模型”页 |
| 顶栏 | 分工 | 为当前任务逐角色指定模型（有任务时出现） |
| 顶栏 | 偏好 | 记录本篇的用户偏好（供 JEV 旁路使用，不开放代决；有 v2 任务时出现） |
| 顶栏 | 快捷键 | 列出全部可用快捷键（F1 同效） |
| 顶栏 | ＋ 新文章 | 清空当前选择，准备开始下一篇 |
| 进度 | 步骤条 + 一行状态 | 材料 → 摘要确认 → 写作与审核 → 人工终审 → 保存 → 发布；状态行显示任务 ID、阶段、实际接入的产品与模型、当前节点已运行秒数 |
| 对话区 | AI OS 输出 | 摘要、提问、短样稿、终审稿按 Markdown 渲染；点击正文切到原文（可选中复制），鼠标移开后恢复渲染；右上角“渲染：开/关”可固定显示原文 |
| 输入区 | 文章主题 + 多行文本 | 主题只在新文章时出现；输入框的灰色提示随阶段变化，点进去即消失 |
| 操作行 | 左侧提示 + 当前阶段的按钮 | 见下表 |

| 阶段 | 按钮 |
|---|---|
| 新文章 | ☐ 先确认短样稿（点一下变 ☑）、开始写作 |
| 运行中 | 补充说明 |
| 待确认摘要 | 提交修改意见、确认摘要 |
| 待选短样稿 | 提交修改意见、选 A、选 B |
| 待你决定 | 回复；AI OS 因预算暂停时另有“追加预算” |
| 待终审 | 退回修改、确认署名并保存本地 |
| 已保存 | 发布预览；预览后出现“确认发布” |
| 失败 / 中断 | 追加预算、续跑 |

确认类按钮只批准页面上展示的那个版本。

## 接续已有任务（含验收目录）

TUI 读写 `--directory` 指定目录里的 `tasks.json` 与 `checkpoints.sqlite`，默认是 `.runtime/tui/`（页面里开始的文章都记在这里，顶栏“历史”里能看到）。通过 `scripts/accept_v2.py` 或 MCP 服务创建的任务保存在各自的目录里，用 `--directory` 指向该目录即可在页面上接续，确认、反馈、保存与发布的规则完全一样：

```powershell
uv run python tui.py --directory topic/<主题目录>/process/<验收目录>
```

进入后在顶栏“历史”里选中任务，页面会展示当前待确认内容（例如“第 N 版稿件……确认署名后保存本地”）。要确认署名，点击“确认署名并保存本地”；要改，直接把意见发到对话区，AI OS 会安排修订并重新审核后再交回你。稿首的“润色说明/修改说明”HTML 注释是节点间的工作记录，页面展示与保存时都会剥离。

想让其他目录里的任务或管道外改定的已发布文章也出现在“历史”里，在启动目录（默认 `.runtime/tui/`）写 `history_sources.json`，路径相对仓库根：

```json
{
  "task_dirs": ["topic/<主题目录>/process/v1/run"],
  "articles": [{"path": "output/<主题目录>/v2/article.md", "note": "topic/<主题目录>/process/v2/publication/发布状态.md"}]
}
```

`task_dirs` 里的任务留在原目录，选中时页面切换到该目录（同样加 `.ui.lock`，当前任务仍在运行时不切换）。`articles` 用于没有任务记录的文章，只读展示正文和说明，不提供确认、保存或发布按钮。旧流程（v1）任务在终审点“退回修改”会交回初稿节点重写并重新审核；审核轮次用尽被强制放行的终稿，页面会标明“审核未通过”。

同一目录同一时间只能被一个 TUI 打开（`.ui.lock`）。MCP 服务（`.runtime/service/`）与 TUI 默认目录互不相通（两个进程不能安全共用一份登记簿），接续 MCP 创建的任务时用 `--directory .runtime/service`。

## 模型分工与自动切换

专业节点默认分工以 `config.py` 为准，可在顶栏“分工”里查看。每次真实调用前 AI OS 会解析实际接入：配置分工 → 本任务的覆盖 → 额度核验（Codex 至少 15%、Claude Code 至少 10%）→ 不足或不可验证时按回退链切换（Codex↔Claude Code→DeepSeek API）。每次解析都会在对话区写一行“<角色> 已接入 <产品 / 模型> · 原因”，状态栏同步显示最近一次接入，任务登记簿里也留 `routes` 记录；切换从不静默。回退到 DeepSeek 时使用 `deepseek-v4-pro`（`WRITING_ROLE_FALLBACK_API_MODEL` 可改）。不想自动切换就设 `WRITING_ROLE_FALLBACK=strict`，此时额度不足直接失败并保留断点。

点击顶栏“分工”可为当前任务逐角色指定提供方与模型，或恢复配置分工。设置立即写入任务登记簿，但只在下一个节点边界被读取：正在执行的调用沿用它开始时的分工，不会中途换模型；运行中也可以改。表单底部列出最近的实际接入。

若某家 CLI 当前不可用（例如 Codex 额度用尽），也可只对本次启动显式改分工，不改 `config.py`：

```powershell
uv run python tui.py --directory <任务目录> --role reviewer=claude:claude-fable-5-1 --role final_check=claude:claude-fable-5-1 --role researcher=claude:claude-fable-5-1
```

`--role` 只写入本进程的环境变量（等价于 `WRITING_<ROLE>_PROVIDER/MODEL`），不落任务记录；只有终审确认→保存这一步不调用专业节点，其余修订都会按当时分工调用模型。

1. 填主题，在大输入区粘贴观点与本篇允许使用的材料，点击“开始写作”。
2. AI OS生成完整摘要，展示后等待；普通输入均作为修改意见。只有点击“确认摘要”才批准界面展示的版本。
3. 正式写作由专业节点完成。运行中仍可发送纠正，在节点边界由AI OS合并进共享摘要。页面列出节点状态，原稿与审核结果进入检查点。
4. 若启用了短样稿，阅读两个方案后点“选 A / 选 B”（也可在输入框写 A 或 B），或输入自然语言意见重做。选择只记录本篇偏好，不代替成稿终审。
5. 内部原意、事实及阅读质量通过后，页面展示全文。可继续反馈，或明确确认署名并保存本地。保存不等于发布。
6. 发布须先展示实际稿件和目标预览，再单独明确确认。更换稿件或目标会使旧许可失效。

## 接入设置

每次启动先进入“选择 AI OS 模型”页，分两步。

**第 1 步：接入方式。** 页面先检测本机有没有 Codex 与 Claude Code（只运行 `--version` 和 Codex 的只读模型列表，不发生成请求、不读取登录凭据）。检测到的显示版本并标注“使用本机登录，可自动接入”；没检测到的显示原因且不可选（Codex 已安装但读不到模型列表时，多半是没登录，在终端运行 `codex login`）。另外三种 API 接入始终可选：DeepSeek API、OpenAI 兼容 API（Chat Completions）、Anthropic 兼容 API（Messages）。

**第 2 步：模型。** 只列第 1 步所选方式的可选模型：

- Codex：账户实时返回的模型列表，首项是“账户默认模型”。
- Claude Code：“CLI 默认模型”加 `config.AI_OS_CLAUDE_MODELS` 里的已知标识。
- DeepSeek：`.env` 里已有密钥时自动读取可选模型，否则填密钥后点“读取模型列表”。
- OpenAI / Anthropic 兼容 API：填地址和密钥，点“读取模型列表”；服务不开放模型列表时直接手动输入。Anthropic 兼容地址填到 `/v1` 之前（如 `https://api.example.com/anthropic`），多填的 `/v1` 会自动去掉。

每个列表末尾都有“其他模型（手动输入）”。手写的名字点“接入”时先核对再规范：全角字符、大小写、空格/点号/下划线、缺厂商前缀都会被纠正（如“Opus 5.5”→ `claude-opus-5-5`）。有实时模型列表时，列表外的名字直接拒绝并给出相近候选；没有列表时格式正确就放行，首次调用时由接入方校验。规范结果写进对话区。

这里只是选择：真正接入哪一家以每次调用前的额度核验为准，届时对话区写“已接入”记录。接入方式、模型和地址记在任务目录的 `ai_os_choice.json`，下次启动预选；API key 输入为密码框，只在本次进程内使用，不进入这个文件、任务JSON、检查点或文章。

Codex沿用正常本机CLI登录。受限sandbox可能无法读取该登录，不应把“不可验证”写成“额度耗尽”。Claude Code 的额度以 CLI 每次调用自报的数据为准：管道内的 Claude 调用会自动记录；没有 120 秒内的新鲜数据时，先向 CLI 发一次最小查询（无材料、无工具，计入请求预算）再判 10% 门槛，详见`AIOS_额度接入.md`。

## 恢复与预算

TUI使用`.runtime/tui/tasks.json`及`.runtime/tui/checkpoints.sqlite`，保留历史任务。关闭页面后，下次从顶栏“历史”选择，再续跑被中断或失败的任务。已经完成并保存到检查点的节点不重跑；关闭时尚在执行的节点可能重试并产生费用。

默认全篇36次调度、120次模型请求、4小时模型执行预算。同一问题最多两次针对性修订，仍未解决暂停。错误重试也计请求数，失败耗时保留，人工等待不计入执行。追加预算必须明确授权，不通过重启清零。

任务失败、被中断，或 AI OS 因预算暂停时，操作行会出现“追加预算”。表单展示所选任务 ID、主题、已使用请求次数/执行秒数和当前上限；输入框默认留空。明确填写要增加的请求次数（0至120）或执行秒数（0至86400），至少一项非零，再点击“确认追加（不续跑）”。这次授权通过现有任务管理器记录在该任务的 `budget_events`，保留原有用量。

追加请求次数/秒数后不会自动续跑，也不代表摘要、短样稿或最终稿已获确认。失败或被中断的任务仍需另点“续跑”；等待人工的任务继续回应页面展示的内容。运行中和已经完成的任务不能追加。取消表单不会修改预算；打开表单后若切换了任务，旧表单的提交会被拒绝，需在目标任务重新打开。

AI OS 因“总调度预算已用完”或“同类审核问题两次修订后仍未解决”暂停时，页面会展示暂停原因，此时“追加预算”表单多出两项：AI OS 调度步数（0至100）和每问题修订次数（0至10）。这两项属于图内预算，填写并确认后会连同这次授权一起交回暂停点，AI OS 从暂停点继续（按钮文字为“确认追加（步数/修订会续跑）”）；它同样不构成对任何稿件的确认。只在暂停时才能追加这两项，其他状态下会被拒绝。

专业角色、技能、工具、来源和稿件版本的证据保留在保存目录。页面设置只选AI OS，不静默改变定框架/初稿/审核等专业模型。

## 无网络演练

正常退出请使用 Ctrl+Q：页面停止接受新操作，取消这个 TUI 管理的任务，并最多等待 8 秒收尾。CLI 的子进程和孙进程按本次调用的作用域回收，不影响其他终端的 Codex/Claude。任务记为“中断”，保留已完成节点的断点、请求次数与退出前的执行耗时；再次打开后需要主动续跑。在途结果不会继续进入下一节点。

API 请求一旦发出，退出不能保证远端停止执行或计费。等待到期后页面可以退出；已取消的旧线程即使稍后返回，也不能覆盖新页面的任务登记簿。请求耗时至少记到退出收尾时刻，远端在此之后的执行时间无法由本地确认。

Windows CLI 另外使用独占 Job Object：成功绑定后，宿主强制退出会关闭句柄并回收绑定的进程树。进程启动到绑定之间仍存在很短的竞争窗口，因此不承诺任务管理器强杀、系统崩溃或断电全部覆盖；可靠的操作入口仍是 Ctrl+Q。绑定失败会拒绝发送模型输入。

`uv run python tui.py --mock --directory .tmp/tui-demo`。模拟模式仅供交互和恢复测试；其中假稿件、假审核、模拟点击都不构成真实作者确认或文章质量验收。
