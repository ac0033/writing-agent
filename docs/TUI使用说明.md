# AI OS终端对话

启动：在项目根目录执行 `uv run python tui.py`。Windows无需curses。首次依赖安装使用`uv sync`。

TUI 是与 AI OS 交互的完整入口：开始新文章、审阅并确认摘要、运行中发送纠正、回答 AI OS 的提问、选择短样稿、追加预算、终审确认并保存、发布预览与发布确认，都在页面上完成，不需要再经由 Claude Code / Codex 对话转发。Claude Code、Codex 只作为 AI OS 和部分专业节点的非交互式模型入口被调用。

## 页面元素

| 位置 | 元素 | 作用 |
|---|---|---|
| 顶栏 | 文章主题 | 新文章的标题（单行） |
| 顶栏 | 接入设置 | 选择 AI OS 接入方式，输入临时 API key |
| 顶栏 | 续跑 | 失败或被中断的任务从上一个检查点继续；等待你回应的任务不用它 |
| 顶栏 | 历史任务 | 切换当前目录里的任务；切换后页面重新展示待确认内容 |
| 状态栏 | 一行状态 | 任务 ID、状态、实际接入的产品与模型、当前节点已运行秒数与 CLI 事件数 |
| 对话区 | AI OS 输出 | 摘要、提问、短样稿、终审稿、完成节点、失败原因 |
| 输入区 | 多行文本 | 观点材料、修改意见、对提问的回答；Ctrl+Enter 或“发送 / 开始” |
| 操作行 | 确认当前摘要 / 确认署名并保存本地 | 按钮文字随待确认内容变化；只批准页面上展示的那个版本 |
| 操作行 | 新文章 | 清空当前选择，准备开始下一篇 |
| 操作行 | 先确认短样稿 | 新文章勾选后，摘要确认后先出 A/B 短样稿 |
| 操作行 | 记录为本篇偏好 | 把输入区文字记为本篇的用户偏好（供 JEV 旁路使用，不开放代决） |
| 发布行 | 追加预算 / 发布预览 / 确认发布 | 见下文 |

## 接续已有任务（含验收目录）

TUI 读写 `--directory` 指定目录里的 `tasks.json` 与 `checkpoints.sqlite`，默认是 `.runtime/tui/`（页面里开始的文章都记在这里，“历史任务”下拉能看到）。通过 `scripts/accept_v2.py` 或 MCP 服务创建的任务保存在各自的目录里，用 `--directory` 指向该目录即可在页面上接续，确认、反馈、保存与发布的规则完全一样：

```powershell
uv run python tui.py --directory topic/<主题>/<验收目录>
```

进入后在“历史任务”里选中任务，页面会展示当前待确认内容（例如“第 N 版稿件……确认署名后保存本地”）。要确认署名，点击“确认署名并保存本地”；要改，直接把意见发到对话区，AI OS 会安排修订并重新审核后再交回你。稿首的“润色说明/修改说明”HTML 注释是节点间的工作记录，页面展示与保存时都会剥离。

同一目录同一时间只能被一个 TUI 打开（`.ui.lock`）。MCP 服务（`.runtime/service/`）与 TUI 默认目录互不相通（两个进程不能安全共用一份登记簿），接续 MCP 创建的任务时用 `--directory .runtime/service`。

## 模型分工与自动切换

专业节点默认分工以 `config.py` 为准，页面挂载时会打印。每次真实调用前 AI OS 会解析实际接入：配置分工 → 本任务的覆盖 → 额度核验（Codex 至少 15%、Claude Code 至少 10%）→ 不足或不可验证时按回退链切换（Codex↔Claude Code→DeepSeek API）。每次解析都会在对话区写一行“<角色> 已接入 <产品 / 模型> · 原因”，状态栏同步显示最近一次接入，任务登记簿里也留 `routes` 记录；切换从不静默。回退到 DeepSeek 时使用 `deepseek-v4-pro`（`WRITING_ROLE_FALLBACK_API_MODEL` 可改）。不想自动切换就设 `WRITING_ROLE_FALLBACK=strict`，此时额度不足直接失败并保留断点。

点击顶栏“模型分工”可为当前任务逐角色指定提供方与模型，或恢复配置分工。设置立即写入任务登记簿，但只在下一个节点边界被读取：正在执行的调用沿用它开始时的分工，不会中途换模型；运行中也可以改。表单底部列出最近的实际接入。

若某家 CLI 当前不可用（例如 Codex 额度用尽），也可只对本次启动显式改分工，不改 `config.py`：

```powershell
uv run python tui.py --directory <任务目录> --role reviewer=claude:claude-fable-5-1 --role final_check=claude:claude-fable-5-1 --role researcher=claude:claude-fable-5-1
```

`--role` 只写入本进程的环境变量（等价于 `WRITING_<ROLE>_PROVIDER/MODEL`），不落任务记录；只有终审确认→保存这一步不调用专业节点，其余修订都会按当时分工调用模型。

1. 填主题，在大输入区粘贴观点与本篇允许使用的材料，点击“发送 / 开始”。
2. AI OS生成完整摘要，展示后等待；普通输入均作为修改意见。只有点击“确认当前摘要”才批准界面展示的版本。
3. 正式写作由专业节点完成。运行中仍可发送纠正，在节点边界由AI OS合并进共享摘要。页面列出节点状态，原稿与审核结果进入检查点。
4. 若启用了短样稿，阅读两个方案后输入A/B选择，或输入自然语言意见重做。选择只记录本篇偏好，不代替成稿终审。
5. 内部原意、事实及阅读质量通过后，页面展示全文。可继续反馈，或明确确认署名并保存本地。保存不等于发布。
6. 发布须先展示实际稿件和目标预览，再单独明确确认。更换稿件或目标会使旧许可失效。

## 接入设置

默认自动：Codex → Claude Code → DeepSeek。每次调用重新检查真实额度，Codex不足15%、Claude不足10%或额度未知则不接入对应CLI。手动选择被拒绝时可回“接入设置”换另一家。自定义API需地址、模型和key，支持OpenAI兼容Chat Completions。

API key输入为密码框，不进入任务JSON、检查点或文章。退出后需要重新输入临时key；已配置在仓库外的DeepSeek key仍可作为默认回退。切换设置作用于下一次开始或续跑，在途调用保持原接入方式，避免把同一在途请求重复转发。

Codex沿用正常本机CLI登录。受限sandbox可能无法读取该登录，不应把“不可验证”写成“额度耗尽”。Claude Code 的额度以 CLI 每次调用自报的数据为准：管道内的 Claude 调用会自动记录；没有 120 秒内的新鲜数据时，先向 CLI 发一次最小查询（无材料、无工具，计入请求预算）再判 10% 门槛，详见`AIOS_额度接入.md`。页面显示的是实际接入的产品与模型：调用前只写选择顺序，额度检查后才写“AI OS 已接入 Claude Code / <模型>”。

## 恢复与预算

TUI使用`.runtime/tui/tasks.json`及`.runtime/tui/checkpoints.sqlite`，保留历史任务。关闭页面后，下次从历史任务选择，再续跑被中断或失败的任务。已经完成并保存到检查点的节点不重跑；关闭时尚在执行的节点可能重试并产生费用。

默认全篇36次调度、120次模型请求、4小时模型执行预算。同一问题最多两次针对性修订，仍未解决暂停。错误重试也计请求数，失败耗时保留，人工等待不计入执行。追加预算必须明确授权，不通过重启清零。

任务失败、被中断或等待人工时，可点击“追加预算”。表单展示所选任务 ID、主题、已使用请求次数/执行秒数和当前上限；输入框默认留空。明确填写要增加的请求次数（0至120）或执行秒数（0至86400），至少一项非零，再点击“确认追加（不续跑）”。这次授权通过现有任务管理器记录在该任务的 `budget_events`，保留原有用量。

追加请求次数/秒数后不会自动续跑，也不代表摘要、短样稿或最终稿已获确认。失败或被中断的任务仍需另点“续跑”；等待人工的任务继续回应页面展示的内容。运行中和已经完成的任务不能追加。取消表单不会修改预算；打开表单后若切换了任务，旧表单的提交会被拒绝，需在目标任务重新打开。

AI OS 因“总调度预算已用完”或“同类审核问题两次修订后仍未解决”暂停时，页面会展示暂停原因，此时“追加预算”表单多出两项：AI OS 调度步数（0至100）和每问题修订次数（0至10）。这两项属于图内预算，填写并确认后会连同这次授权一起交回暂停点，AI OS 从暂停点继续（按钮文字为“确认追加（步数/修订会续跑）”）；它同样不构成对任何稿件的确认。只在暂停时才能追加这两项，其他状态下会被拒绝。

专业角色、技能、工具、来源和稿件版本的证据保留在保存目录。页面设置只选AI OS，不静默改变定框架/初稿/审核等专业模型。

## 无网络演练

正常退出请使用 Ctrl+Q：页面停止接受新操作，取消这个 TUI 管理的任务，并最多等待 8 秒收尾。CLI 的子进程和孙进程按本次调用的作用域回收，不影响其他终端的 Codex/Claude。任务记为“中断”，保留已完成节点的断点、请求次数与退出前的执行耗时；再次打开后需要主动续跑。在途结果不会继续进入下一节点。

API 请求一旦发出，退出不能保证远端停止执行或计费。等待到期后页面可以退出；已取消的旧线程即使稍后返回，也不能覆盖新页面的任务登记簿。请求耗时至少记到退出收尾时刻，远端在此之后的执行时间无法由本地确认。

Windows CLI 另外使用独占 Job Object：成功绑定后，宿主强制退出会关闭句柄并回收绑定的进程树。进程启动到绑定之间仍存在很短的竞争窗口，因此不承诺任务管理器强杀、系统崩溃或断电全部覆盖；可靠的操作入口仍是 Ctrl+Q。绑定失败会拒绝发送模型输入。

`uv run python tui.py --mock --directory .tmp/tui-demo`。模拟模式仅供交互和恢复测试；其中假稿件、假审核、模拟点击都不构成真实作者确认或文章质量验收。
