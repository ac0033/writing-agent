# JEV 个人偏好验收计划

状态：程序设置与统计入口已实现；个人验证尚未进行，JEV 默认 off。此计划中的规模与阈值是待用户审阅的建议，不是已批准或已测得的效果。当前重写材料向 Codex、DeepSeek、Claude 的授权不包含 TypeSafe/JEV。

## 用户设置与生效

`service/jev_settings.py` 的 `apply_settings` 接收真实用户操作和 `user_event_id`，记录偏好原话、`source_ref`、`scope`（global 或具体 topic_id）及纠正关系。纠正使旧记录失效并保留历史；模型代决不得作为用户偏好。偏好变化清除旧外发授权、关闭已开放类别，需重新评估。

`runtime_state` 输出供 TaskManager 在安全边界同步的 `confirmed_preferences`、`jev_external_authorization`、`jev_settings`。授权必须注明 typesafe、decision_id、purpose 和当前材料指纹；改摘要、候选、偏好或稿件版本后不能重用旧授权。`evaluate_decision` 使用 request.settings 的模式和类别优先于全局配置，不改变其他会话的开关。设置保存在宿主提供的独立路径，原子替换；读回时重放本地操作记录并核对。宿主应锁住同一文件的读改写，模型无权调用用户设置入口；本地审计不是防恶意编辑的密码学证明。

## 样本与防泄漏

建议首轮仅研究 opening；其他三个允许类别分别验收，不能沿用 opening 成绩。

1. 用户另行批准拟使用的历史材料及向 TypeSafe 发送的内容。发现集每类别建议 30 个真实选择，只用于整理偏好和确定阈值；去除同一问题的复述或近重复。
2. 冻结偏好版本、候选资格规则、模型版本、提示词、AI OS 设置、规则基线和两项阈值。规则基线按用户已明确且适用的规则选项，无唯一合格项则请求用户；不能以任意第一项作为强基线。
3. 收集之后自然发生的验证决定，每类别建议至少 100 个有真实用户标签的决定。使用不同文章/主题且与发现集无同源问题；程序拒绝相同 decision_id，但语义近重复仍需人工核对。不能为了凑样本反复询问已决定的事情。
4. 用 `prediction_input` 白名单同时生成三者输入，隔离 user_choice、后续纠正和预测记录；预测按输入指纹与先后序号先固化，再记录真实用户选择。用户答案与事后纠正不能写入预测时偏好。程序可检查结构与记录顺序，不能仅靠提交方自报序号证明采集过程真实，验收时必须核对宿主日志。
5. 保留全部候选、摘要与稿件版本、当时可见偏好和来源；对新增事实/核心立场/固定确认直接请求用户，不计成可代决任务。预测不能控制写作，用户看不到预测推荐以免影响标签。

示例（虚构，仅说明数据流）：当时偏好 p1 为“开头先提出具体问题”，两个合格开头 a/b → JEV、AI OS、规则分别固化 a/b/a → 用户后来选择 a → 验证表记录三者一致数为 1/0/1。同一次选择若已进入发现集，不得再次记作验证成功；后来把 p1 修正为“先讲案例”也不能回填到旧预测输入。

## 报告与开放条件

`evaluation_report` 按类别和 JEV/AI OS/rules 三组分别输出：有标签数、与用户选择一致率、候选选择覆盖率、应询问却选择的次数和比例、不必要询问次数和比例。上述比例分母均为该类别有标签数；撤销比例以该类别实际记录的 JEV 候选选择数为分母。旁路阶段未实际执行，不应将用户选择不同伪称“撤销”；实际试用后以明确撤销操作补记录。

建议审核门槛：每类别至少 100 个独立验证决定、应询问却选择为 0、选择一致率至少 95%，且不劣于两项基线；同时展示计数、覆盖率与二项不确定性区间，不能把小样本的 0 错误解释为风险为零。阈值建议初始 probability≥0.95、confidence≥0.90，仅供发现集调参；验证中调参必须重开独立验证集。以上门槛需用户先批准，再进行相应试验。

实际报告和计划路径提交给用户；类别设置必须同时包含 shadow_allowed、evaluation_passed、user_approved、enabled 以及阈值和两份路径。程序不会根据统计报告自动启用。通过类别只允许可逆表达选择，不开放观点、事实、摘要确认、署名或发布。一次用户撤销应暂停对应类别，复核原因与受影响稿件；重新开放须重新确认。

## 程序测试与真实验收分开

`test_jev_workflow.py` 使用虚构本地样本覆盖纠正、作用域、持久化、授权撤销、权限门、答案剥离、发现/验证隔离、基线完整性与撤销统计。`test_jev_adapter.py` 验证适配器权限及失败降级，mock 禁止真实网络。这些测试证明程序约束，不证明个人偏好预测有效；只有上述真实评估和用户明确接受后才能称相应类别已通过个人验收。

## 本地采集入口与报告命令

生产宿主可调用 `collect_prediction(path, sample, model, choice, record_ref)`，将三种实际输出分别保存到同一账本；model 只能是 jev、ai_os、rules。sample 是 `prediction_input` 所列字段，可另含 group_id（同一文章/问题来源的分组）；不得包含用户答案或事后纠正。record_ref 必须指向实际模型输出或规则执行记录。函数不会自行调用模型，也不会产生预测。

三者输入及预测固定之后，用户自然作出决定，宿主调用 `record_user_choice(path, decision_id, choice, user_event_id=..., source_ref=..., user_text=...)`。必须填写真实用户事件、出处和原话；不能由agent填自己推测的选择。程序分配持久化序号和UTC时间，拒绝补写标签之后的预测、覆盖已有预测/标签或重复使用用户事件。写入期间用独占锁防覆盖，异常遗留锁需核实没有写入进程后再清理。账本文件可被本地编辑，因此真实验收仍需回查来源，不能凭字段自证真实用户选择。

发现集、验证集分别存为两个账本。已有合法记录可以是 `{ "records": [...] }` 账本或记录数组。报告生成命令（路径为使用者实际准备的文件，不代表仓库已有这些真实样本）：

```powershell
uv run python scripts/jev_evaluate.py --discovery evaluation/discovery.json --validation evaluation/validation.json --output evaluation/report-001
```

如有真实试用后撤销记录，增加 `--revocations evaluation/revocations.json`。输出新目录内的 `report.json` 和 `report.md`，拒绝覆盖旧报告，不调用网络、不更改 JEV 配置。拒绝跨集相同决定、同组问题及只修改decision_id的重复输入；语义近重复仍需人工检查。未获得用户标签的验证样本单独计数，不计入指标分母。缺少实际样本时可以准备空数组，但空报告没有个人验证效力。
