# V2 调度实现说明

本文说明已经实现的程序行为和验收边界，不等于真实文章质量已经通过。

## 已实现的主流程

`build_graph_v2()` 保留旧图，新增「摘要 → 人工确认 → AI OS → 专业节点 → AI OS → 人工终审 → 保存」流程。AI OS 使用配置中的 orchestrator 角色和 `prompts/orchestrator.md`，专业节点复用现有实现，统一获得当前共享摘要及本次任务。

定框架、研究、写作、审核、润色、成稿核验仍是独立工作节点。AI OS 只统筹，不直接写公开正文。摘要需要真实人工确认，不使用自动大纲确认替代。用户终审反馈用自然语言输入，程序更新共享摘要并使旧审核失效。

## 质量和权限约束

- 内容审核必须同时给出原意、事实、阅读质量三维 PASS，缺一不可。润色后针对实际润色稿重新审核，随后进行成稿核验。
- 摘要、当前正文、审核和人工批准以版本与 SHA256 指纹绑定。旧 PASS、旧批准不能保存新内容。
- 用户要求修订后，稿件未发生任何文本改变会报错，不能将原稿原样返回后宣称完成。
- 已润色且通过审核的稿件不开放无依据重复润色路线；用户新反馈后可以重新修订。
- 研究、结构或正文改变均使相关审核失效，重新定框架后必须重新写稿。
- JEV 的外发授权和用户偏好由程序状态提供，不接受 AI OS 自填许可。默认状态不允许用户材料外发或实际代决。可执行选择还要匹配当前版本与有效候选。
- 用户反馈保留原话；明确修正优先于旧要求，探索性问句不自动成为已确认立场。其语义判断仍需要 AI OS 和审核，程序不声称能够自动证明作者原意。

## 预算与恢复

AI OS 调度次数、节点实际耗时、审核失败次数进入检查点。人工等待不计执行耗时。

同一审核类别初次失败后，默认最多两次修订仍失败就暂停。这里目前采用审核类别计数，比逐个语义问题跟踪更保守；尚未实现跨改写稳定识别同一自然语言问题。

普通用户反馈和修改摘要不清空失败记录。实际审核 PASS 才清除对应类别的连续失败次数。用户可通过明确的 `additional_steps`、`additional_seconds`、`additional_revisions` 扩充预算；扩额记录保留，不重置历史用量。

## 运行中的用户反馈

`feedback_reader` 是服务在运行上下文绑定的只读队列回调，返回 `[{id, text}]`。管道通过 `apply_user_update()` 更新共享摘要。

AI OS、人工摘要确认、人工终审、保存入口都会检查队列。正在运行的模型调用不会即时读到新反馈；它完成后，下一节点边界消费反馈并使该结果的旧审核失效，重新安排必要修订。

消费记录包含 `user_feedback_id`，checkpoint 持久化后服务才移除对应队列项。重复读取同一 ID 不重复追加。摘要阶段收到反馈时重新生成待确认摘要，不能自动批准。终审或保存前收到反馈时返回 AI OS，不沿用旧批准。

服务层已提供 `save_gate`：最后检查反馈与设置 `save_started` 在 TaskManager 共用锁内原子完成。反馈先到则返回 AI OS 修订；保存先开始则明确拒绝晚到反馈，不会误报已入队。模型执行和保存 IO/记忆收尾不持有该锁，其他任务和运行中反馈不因此等待。队列清理也使用同一锁，避免并发新反馈被覆盖。此保证适用于单一 TaskManager 服务实例；多服务实例共享登记簿仍不受此进程内锁保护。

v2批准需要客户端传入实际审阅版本：摘要确认须 `expected_summary_version`，终审须再传 `expected_article_version`。服务入口和图节点双重校验；CLI使用刚展示的payload，验收脚本要求批准JSON自带版本，不从后来的状态替作者补填。

## 已验证和仍待验证

`test_pipeline_v2.py` 的 21 项 mock 测试验证：固定人工确认、全图运行、润色后独立审核、三维审核缺失失败、指纹变化、用户反馈、预算不重置、JEV 授权隔离、无改动修订拒绝、运行中反馈去重、终审和保存前反馈竞态、旧版本确认拒绝。

补充服务集成测试后，`test_service_v2.py` 与 `test_pipeline_v2.py` 共 38 项通过。使用真实 TaskManager、线程、SQLite 与 mock 模型，验证重启、旧图隔离、原始材料保护、服务/CLI版本批准，以及线程屏障下的模型执行期间反馈、保存前反馈退回和保存开始后明确拒绝。全部使用临时检查点与输出目录，不触碰真实任务，不发布。

这些测试证明流程约束能够执行，不证明模型真的理解作者、阅读质量足够好或 JEV 代表用户偏好。真实 vibe coding 文章仍须完成摘要确认、研究、写作、内部审核、主 agent 独立复核及作者终审。发布仍须另行授权。

AI OS 提示词只带最近 8 个节点的元信息和结论摘要，检查点继续保留完整历史。JEV off 模式不进入合法调度动作；shadow 模式只记录预测，不等待代决。
