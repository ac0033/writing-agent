# 使用指令指南

本指南对应当前代码。安装、模型配置与完整边界见 [README](../README.md)。以下终端命令都在 writing 项目根目录执行。

## 1. 检查环境

```bash
uv sync
uv run python -m tools.doctor
uv run python main.py --mock
```

真实模型配置读取 `WRITING_ENV_PATH` 指向的仓库外环境文件，默认是用户主目录下的 `.env`。需要的键为 `DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`、`TAVILY_API_KEY`。知识库位置由 `WIKI_DIR` 配置；博客位置由 `BLOG_REPO_PATH` 配置。

## 2. 从聊天整理主题

MCP 服务启动命令：

```bash
uv run python -m service.writing_server
```

连接服务后，按以下顺序操作：

1. `writing_topic_guide()`：读取提炼规范。
2. 根据真实聊天与作者材料整理主题，逐个论点附具体素材、支持关系和出处。
3. `writing_prepare_topic(topic, pyramid_markdown, topic_id)`：保存主题 Markdown，并向用户展示返回的文件路径。
4. 已获写作授权后，`writing_start(topic_file=返回的路径, auto_approve=False)`：开始任务。

MCP 入口必须传保存后的 `topic_file`，不支持用 `idea` 直接绕过主题文件。保存主题仅代表主题已落盘，不代表最终文章或发布已获确认。

## 3. 查看进度与确认稿件

- `writing_status(task_id)`：查看任务进度、待审内容与质量问题。
- `writing_resume(task_id, 用户决定)`：按当前待确认节点返回的格式继续。
- 最终稿经用户确认并同意保存后，使用 `writing_resume(task_id, {"route":"approve"})`。
- `writing_result(task_id)`：获取本地稿件、核验状态与下一步信息。

`auto_approve=True` 只自动通过大纲，最终稿仍等待人工确认。模型审核和程序检查不能证明所有事实正确。

## 4. 终端入口与续跑

```bash
# 手工输入主题与思路
uv run python main.py
# 使用已整理的主题文件，替换为实际文件路径
uv run python main.py --topic-file "topic/已整理主题.md"
# 查看已有会话
uv run python main.py --list
# 使用实际会话 ID 续跑
uv run python main.py --thread-id YOUR_THREAD_ID
```

同一主题的系列文章可复用 `--topic-id`。已有会话从 checkpoint 继续；不要删除会话记录来代替续跑。

## 5. 保存后独立发布

保存结果位于 `output/日期-主题-运行标识/版本标识/`，包括 `article.md`、`evidence.json`、`reading.md` 和 `thinking.md`。发布尝试另写 `publication.json`。

1. `writing_publish_preview(task_id)`：展示正文版本、目标仓库、分支、文件与 `approval_token`。
2. 用户对该预览明确同意发布后，`writing_publish(task_id, approval_token, confirmed=True)`。

CLI 的真实稿件保存后也会展示发布预览，输入“发布”才执行。`--push` 不跳过确认。目标有冲突、正文变化或包含无关未推送提交时会停止。`pushed` 表示 Git 远程提交已核实，不代表静态站点部署完成。

## 6. 来源回库与重试

保存真实稿件后，写作流程可调用相邻知识库的 `scripts/import_writing.py`。回库失败时保留本地证据包；在 llm_wiki 项目根目录中重试：

```bash
uv run python scripts/import_writing.py "稿件目录/evidence.json" --dry-run
uv run python scripts/import_writing.py "稿件目录/evidence.json"
```

将示例路径替换为实际证据包路径。导入的是来源片段、draft 笔记与待读清单，不会把片段当作全文或将草稿标记为已核实。

## 7. 自动测试

```bash
uv run pytest
```

测试进入 mock 模式；发布测试使用临时本地 Git 远端。真实模型质量仍需结合实际选题审阅。若个人移动了 `topic/` 素材，需要同时检查依赖这些路径的本地实验脚本；目录迁移不会自动修复脚本中的路径。
