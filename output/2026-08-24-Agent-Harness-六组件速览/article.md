# Agent Harness 六组件速览，一个执行循环里的六块拼图

模型再强，也有些事它自己做不了。开一个终端、装上依赖、读懂一条失败的测试输出、决定下一步干什么，这些活它都碰不到。模型负责想和说，想与真实世界之间还隔着一堆事，环境交互、状态保存、权限把关，都要另一层系统来承担。

这层东西叫 **Harness**，执行壳，也可以叫运行时脚手架。按综述[《From Question Answering to Task Completion》](https://arxiv.org/abs/2606.20683)的说法，它用六个运行时组件，把模型和外部世界之间的闭环交互接起来。这层不是可有可无的。SWE-agent 早就证明过，[固定基座模型、只重新设计模型与环境之间的接口](https://arxiv.org/abs/2405.15793)，SWE-bench 上的分数就能明显往上走。本文沿用这份综述的六组件划分，顺着执行循环走一遍，看六块组件各管什么。

## 主执行链路上的四个组件

六个组件不是平铺的。前四个，观察、上下文、控制、动作，构成一条主执行链路，正好是一轮运行时循环的时序；后两个横切主链路，做支撑。先沿主链路走一遍。

### 1. Observation Interface（观察接口），管"看到什么"

职责一句话，把环境和工具的原始输出，翻译成模型可读的统一观察表示。终端日志、网页 DOM、屏幕截图、API 返回，格式五花八门，模型没法直接消化，观察接口负责把它们翻成一致的格式。它的边界很干净，**不决策、不执行，只翻译输入**。举个例子，一条命令吐出上千行日志，观察接口决定它以什么形态进入下一步，截断、提取关键行，还是结构化呈现。冗长的工具返回要是原文样塞进上下文，只会稀释有效信息。

### 2. Context Manager（上下文管理器），管"给模型看什么"

职责一句话，组装每一轮喂给模型的上下文。对话历史、工具描述、记忆注入、压缩截断，都发生在这里。边界也清楚，**它不生成任何内容，只决定什么东西进上下文窗口**。工具描述要不要放进窗口，保留最近几步历史，还是把早期记录摘要成一句话，这些取舍直接影响模型这一步的判断质量。

### 3. Control Loop（控制循环），管"怎么推进"

职责一句话，驱动"观察 → 推理 → 行动"的循环，决定何时进入下一轮、何时停止、何时重试。最小实现就是 [ReAct](https://arxiv.org/abs/2210.03629) 式的"推理、行动、观察"交替轨迹。边界在于，**它不产生具体动作，只负责推进流程**。停止条件归它管，任务完成信号、步数与成本预算都算；失败恢复也归它管。一条命令失败后，是原地重试，还是带上报错信息再来一轮，由控制循环的策略说了算。

### 4. Action Interface（动作接口），管"做什么、怎么做"

职责一句话，把模型输出的动作（工具调用、代码、命令）解析成可执行格式，派发到目标执行器。它解析工具调用的 JSON、做 schema 校验、分发到终端或浏览器。**动作的提案来自模型，动作接口只管落地**。这里有一笔账要算，动作能力越强，风险面越大。综述指出，更具表达力的动作在扩展能力的同时，要求更强的权限控制、沙箱、回滚与审计。这正好引出下面两个横向组件。

## 横向支撑的两个组件

主链路四组件在前台，剩下两个不在主链路上，横切所有环节兜底。

### 5. State & Artifact Store（状态与工件存储），管"记住什么、留下什么"

职责一句话，持久化任务状态与中间产物。计划、检查点、日志、生成的文件、执行轨迹，都存在这里，供后续步骤、回放与审计使用。上一步改过哪些文件、长任务中断后从哪个检查点恢复，都靠这一层。它还会反哺主链路，历史状态可以重新注入上下文，轨迹则是验证环节的判断材料。

### 6. Verification & Governance（验证与治理），管"什么能放行"

职责一句话，决定哪些动作可以被执行。沙箱隔离、权限门、审计、回滚、合规检查，都在这里。执行危险命令或对外网络请求之前，先过一道权限门；敏感信息在离开上下文前脱敏。它与动作接口耦合最紧，动作的表达力越来越强，它就得越盯越紧。它也和可观测性交叉，要审计，先得有得查的记录。

## 拼回全景

把六块拼图装回去。环境经观察接口翻译成模型可读的输入，上下文管理器决定模型这一轮看到什么，控制循环推着循环一轮轮前进，动作接口把模型的决策落回环境，状态存储在旁记录轨迹，治理层把守每一道放行关口。这就是一个 agent 运行时的闭环。

最后提醒一句。六组件是上述综述的一种划分，不是唯一共识。社区对 harness 的切分还有七层 ETCLOVG、code-as-harness 等不同思路，命名与粒度各有出入。想深入的读者，除了[综述原文](https://arxiv.org/abs/2606.20683)，可以从 [Awesome-Harness-Engineering](https://github.com/Jiaaqiliu/Awesome-Harness-Engineering) 资源清单继续挖。
