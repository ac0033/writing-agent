# 文章组织与表达

用已确认摘要决定讲什么，用原始材料核对事实，用范文学习怎样讲。用户当前明确表达要求优先于通用风格建议；事实不能为风格让步，证据与作者判断冲突时交 AI OS 处理。

## 各角色如何使用

- 定框架：选择一个贯穿全文的问题。说明每一节解决什么、为什么接在上一节之后，安排案例的独有作用。用户给的清单是覆盖依据，不天然是目录。
- 写作：初稿就负责自然叙述。每段提供新理由、展开一个例子或推进前文问题。先选择必要材料，再写句子；不用项目状态和核查口径填满文章。
- 内容审核：分别判断原意、事实和阅读质量。定位重复或断裂发生在哪里、为什么影响理解；不能以事实全通过代替文章合格。
- 润色：改善词序、节奏、段内衔接和重复表达。需要改变章节关系或论证时报告 AI OS，不能靠一句“接下来”掩盖结构问题。

## 具体做法

开头尽早让读者知道文章要解决的真实问题。案例围绕一个判断展开：发生什么、为何这样处理、由此可以理解什么；只写材料支持的经历。必要数字保留对象和范围，不承担论证的细节留在证据记录。修订不等于逐条向读者回应审核意见：通过删除无关断言、收窄表述来修复，避免把“没有这份对照”“没有相应记载所以不下结论”等内部取证答复连续搬入正文。只有影响读者判断的限制需要在正文解释。

结构可以围绕问题组织，但不要机械地给每节加“第几个问题是”，也不必在正文解释为何采用此目录或声称下一节将讲什么。

段落接续依靠内容关系：上一段留下的疑问、条件或选择，由下一段继续回答。章节共享同一批材料时先检查是否重复，必要时把判断融入对应案例，不强制清单与讨论各写一遍。

推理可以换用清楚的新表达，不要求每句复制作者原话。新增关键立场、实际经历或心理感受仍须作者依据。统一已确定的名称；聊天里的临时分类是否进入公开正文，按当前摘要决定，不能擅自扩展出新等级。

结尾回应文章建立的问题，保留适用条件；不重复整篇目录，不凭空拔高意义。列表、标题和标点按内容需要使用，不机械限制条目数，不为了“像人”增加混乱或虚构感受。

## 改写示例（教学用，不是验收稿）

下列“改后”只是教学示例，不是已通过核验的新稿；验收稿必须由管道生成。

原句：“成本上有一组数字可以看。这次把一本四百多页的书整本翻译，全书几千个翻译单元，记录里的实际 API 费用约 1.5 美元，预算 3.75 美元；早期两次样本试译的费用另外分开记。这组数字说明的只是这一次全书翻译调用的支出：它不能证明这种分工带来了降本。”

改后示例：“这次整本翻译的 API 支出约 1.5 美元。这能帮助判断一次完整任务的成本；要比较不同模型分工是否省钱，还需要相同任务的对照。”

修改理由：保留对象、实际支出和推断边界，删去本段没有用于比较的预算与样本费用；没有把单次费用改成分工带来的收益。如果本段真正论证预算执行，则预算数字不能删除。

原句：“流程大致十步，观点落在四个判断上。”后文分成十步与四个判断，多次使用相同项目。

改后方案示例：按开发过程中逐步出现的问题组织章节，把判断放在相应决策处解释；十步和四个判断仅作内部覆盖检查。这是结构处理，不是给原句换一个更漂亮的过渡句。

## 范文使用

先查适合体裁的作者旧文，再读连续章节。记录来源、实际阅读范围及借鉴的组织方式；节选尚未覆盖全文时不声称通读。风格参考不是事实证据，不复制论点、句子或故事。没有适合范文时按当前摘要和本规范工作，如实记录即可。
