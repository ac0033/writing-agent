# 聊天到写作主题：金字塔提炼规范

面向能够读取当前聊天的外层 agent。先读取用户指定的聊天及材料；写作服务不能自行读取宿主聊天。不要仅把最后一句话传给写作管道。

1. 定总主题和一句核心命题，保留用户的主张、限定条件与纠正。未获用户认可的助手观点标为建议，不冒充作者观点。
2. 纵向展开总命题 → 分论点 → 子论点；横向按同一划分标准分组，说明组间逻辑，不强制三个分论点。各节点只保留核心观点，先形成可扩写框架，不写成长篇文章。
3. 每个叶子论点绑定具体对话素材，并解释“这份材料为什么支持这个论点”。保留场景、人物角色、动作、比较条件和必要数字，不能只写“有案例证明”。
4. 标明材料性质：用户经历、对话主张、假设例子、类比、机制推演、待外部核验等。对话里举的数字不当实测结果，旧引用标记不当已核实来源。没有具体材料时直接写“缺口：待研究员补充”，不虚构。
5. 保留关键公式、概念模型和反例，说明公式是概念关系还是经过验证的定量关系。无法读取的聊天或链接明示未读取，不声称已经参考。
6. 提供聊天标题/链接、消息或章节位置；每条素材提供可定位出处。只引用与主题有关的必要片段，避免复制无关私人聊天。
7. 调用 writing_prepare_topic 保存 Markdown，向用户给出实际路径和核心命题。已获写作授权则用 writing_start(topic_file=返回路径) 开始；若只要求整理主题，到保存为止。不新增默认审批门，也不省略成稿和发布确认。

Markdown 固定二级章节（不得缺少；无内容时明确写“无”或“待补充”）：

```markdown
## 核心命题
一句话结论，以及本文要回答的问题与读者。

## 金字塔总览
- 总命题
  - 分论点 A：为什么……
  - 分论点 B：如何……

## 分层论点与具体论据
### 分论点 A
- **论点**：一句可讨论的判断。
  - **具体素材**：具体场景、对比或原话；没有则写缺口。
  - **支持关系**：素材通过什么机制支持论点，能支持到哪里。
  - **材料性质**：如假设例子／用户经历／待核验的对话主张。
  - **对话定位**：聊天标题、用户或助手发言、消息序号或原句定位。

## 关键模型
保留公式、箭头关系；没有则写无。

## 边界与待验证问题
反例、争议、证据缺口和需要外部核验的事实。

## 对话来源
实际已读聊天的标题、链接或当前会话范围；未读取范围单独标明。
```
